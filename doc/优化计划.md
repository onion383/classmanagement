# 班集 · 优化计划（待实施）

本文是「**待办**优化计划」，与 [优化文档.md](./优化文档.md)（记录**已实施**的优化）互补：
- [优化文档.md](./优化文档.md)：已落地的打包体积 / 磁盘 / 内存 / 首批加载 / 切换性能优化。
- 本文：代码质量层面的**待启动**优化项，按优先级分级，供逐条「启动优化」后执行。

## 流程约定（沿用 problem.md）

- 每条优化需用户**明确启动**后才执行；启动后在对应条目追加 `正在优化`。
- 修改完成后追加 `已尝试优化`；用户测试无误后自行追加 `已确认优化`，该项才算闭环。
- 曾被验证依旧存在残留问题的，**不在子项追加「已尝试修复」标记**，待用户确认后再标记。
- 优先「小步迭代」：第一阶段仅做纯代码搬运、不改逻辑，确认无回归后再做后续清理。
- 结构类改动优先保证**行为一致**（启动耗时、交互观感不变），零视觉改动。

## 分级总览

| 级别 | 方向 | 目标 | 风险 | 主要项 |
| --- | --- | --- | --- | --- |
| P0 | 结构治理 | 拆分超大文件，降低单文件维护成本 | 中（需保证行为一致） | A1–A10 |
| P1 | 一致性与去重 | 收敛重复模式与散落的常量/样式 | 低 | B1–B3 |

> 因此计划重点放在**「规模增长期」的维护成本**（大文件、缺测试、全局样式耦合），而非推倒重来。

- **现状**：4 套主题靠全局 CSS 覆盖（[theme-glass.css](../student-frontend/src/styles/theme-glass.css) 1068 行、[theme-night.css](../student-frontend/src/styles/theme-night.css) 737 行、[theme-glass2.css](../student-frontend/src/styles/theme-glass2.css) 609 行等），色值/圆角/间距散落在各大文件内。
- **问题**：视觉微调时改动面大、易遗漏；同一语义色在多份主题文件里重复定义。
- **方案**：抽象 design token（颜色 / 圆角 / 间距 / 阴影），各主题只覆盖 token 变量；逐步迁移，不改视觉。
- **风险**：**严禁改变现有观感**（用户明确要求保留既有视觉效果），迁移需逐屏比对。
- **本轮做法（第一刀）**：先收敛重复率最高的「玻璃层白色/黑色透明度」——同一字面值在主题文件里重复 10–21 次。在 [theme-base.css](../student-frontend/src/styles/theme-base.css) 的 `:root` 增加 `--alpha-white-06/08/10/12/15/30`、`--alpha-black-25` 七个 token（取值与原硬编码逐字一致），再把 [theme-glass.css](../student-frontend/src/styles/theme-glass.css)（62 处）、[theme-night.css](../student-frontend/src/styles/theme-night.css)（44 处）、[theme-glass2.css](../student-frontend/src/styles/theme-glass2.css)（2 处）共 **108 处** `rgba()` 换成 `var(--alpha-*)`；替换数量与原有字面值逐档核对一致，**渲染值不变**。
- **第二步**：把三份主题文件里所有静态 `rgba(255,255,255,X)` / `rgba(0,0,0,X)`（不含 `calc()` 动态值）统一收敛——在 [theme-base.css](../student-frontend/src/styles/theme-base.css) 补齐 **56 个** `--alpha-*` token（每个 token 取值与原字面值逐字一致），再以脚本批量替换 [theme-glass.css](../student-frontend/src/styles/theme-glass.css) / [theme-night.css](../student-frontend/src/styles/theme-night.css) / [theme-glass2.css](../student-frontend/src/styles/theme-glass2.css) 共 **204 处**；替换后三份主题文件残留的同形式字面量为 0。因为 token 值与原字面值完全相同，**渲染像素不变**（零视觉改动）。
- **后续**：`.vue` 组件里的硬编码颜色本轮未动；hex 色值与非透明度语义色待后续按「同一语义 → 同一 token」迁移。
- **状态**：已尝试优化（token 层已建；三份主题文件里的静态白/黑透明度 rgba 已全部收敛，`.vue` 与 hex 待迁）

### D1.1. 网状表格 `GridView` 的高度上限（虚拟滚动评估结论）

- **问题**：`GridView.vue` 原先只有 `minTableHeight`（**最小**高度，空表不塌陷），**没有最高高度**——内容撑多高表格就多高，把外层页面顶长，滚的是整页。
- **本轮做法**：仿 `DynamicTable` 的 `maxHeight` 加内层容器高度上限（默认 560px ≈ 表头 + 12 数据行），超高时容器内纵向滚动 + 表头吸顶；正常规模表格零变化，只有超长才滚。
  - 测量：`measureScrollState` 按 `table.scrollHeight > maxHeight` 判定，超高才加 `scrollbar-gutter: stable`（防滚动条出没引起列宽抖动）。挂载 / 行集合变化 / 列头变化 / `activated`（KeepAlive 切回）/ 窗口 resize（120ms 防抖）时重测。
  - 吸顶表头：`sticky` 加在 `th` 上（与 `DynamicTable` 同款）。课表有 `title` 标题行，量出其高度写入 `--grid-title-h`，列头行的 `top` 据此偏移，避免两行叠在一起。
  - 玻璃主题：半透明表头吸顶会透出下方数据，在 `theme-glass.css` / `theme-glass2.css` 补高遮盖底 + 强模糊（同 `glass2` 给行状表格的处理）。
  - 弹窗内的 `GridView`（`DutyArrangementDialog` / `SmartArrangementDialog` / `AiGridPreview`）传 `:maxHeight="0"` 关闭上限——它们外层已有 `overflow-auto`，再限高会形成嵌套滚动条。
- **虚拟滚动评估结论（暂不做）**：`DynamicTable` 是纯矩形列表，切行无副作用；`GridView` 到处是 rowspan 跨行合并（`_periodRowSpan` 时段列 / `_rowHeaderRowSpan` 行号列分组 / `_aisleRowSpan` 走廊列跨全部数据行），按行切片会让 rowspan 锚点行被切出窗口、组名丢失导致表格结构错位（解法：窗口边界对齐组边界，或把锚点行补渲为不可见占位）。此外拖拽落点测量与编辑中单元格保活都依赖完整 DOM。
  - 且网状表格规模天生小（座位表默认 6 行 × 7 列，课表满课 8~12 节），`tr` 已带 `content-visibility-auto`，DOM 量级远未到需要窗口化的程度。
  - 结论：**先不加虚拟滚动**；若日后实测大表（如全校级值日表）确有卡顿，再按上述 rowspan 对齐方案启动。
- **状态**：已尝试优化
