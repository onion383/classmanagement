## 核心页面机制说明

- **DashboardView**：作为首屏，其数据由 `composables/useDashboardData.js` 的 `ensureDashboardData()` 统一并行拉取（schedule/duty/countdowns/leaves/students/scores/activities/fee-records/album 共 9 个接口）并做模块级缓存，避免与路由懒加载串行等待。班级信息大框可编辑，写回 `widget-settings/class-info`。
- **ClassroomView / SeatView / ScheduleView / DutyView / LeaveManagement / FeeManagement / ScoreManagement**：共同构成「表格 / 网格」两大类交互页。学生信息与班费页走 `useTableCRUD` + `DynamicTable`（动态列 CRUD）；座位、课表、值日走 `useSeatGrid` / 自研网格逻辑 + `GridView`（网格、座位、课表、值日）。
- **表格渲染时序（两类表格一致：表头先行，数据后填）**：页面挂载即渲染表头（`DynamicTable` 的 `fields` / `GridView` 的 `colHeaders` 均有前端默认值，不等接口），行数据就绪后再填入（GridView 侧 `:rows="loaded ? displayRows : []"`）。网格页（座位/课表/值日）不使用骨架屏；历史 tab 仅在「加载完且无快照」时显示 `EmptySnapshot`，加载中仍渲染表头。
- **两类表格的高度与滚动**：`DynamicTable` 与 `GridView` 都有「最小高度」（`minTableHeight`，空表不塌陷）与「最大高度」（`maxHeight`，默认 400 / 560px）。超出最大高度即**容器内纵向滚动 + 表头吸顶**，不再把外层页面顶长。`GridView` 的 `maxHeight` 在弹窗类调用方（`DutyArrangementDialog` / `SmartArrangementDialog` / `AiGridPreview`）传 0 关闭——它们外层已有 `overflow-auto`，再限高会嵌套滚动条。
- **网状表格为什么不做虚拟滚动**：`GridView` 有 rowspan 跨行合并（时段列 / 行号列分组 / 走廊列跨全部数据行），按行切片会让锚点行被切出窗口导致组名丢失、表格结构错位；且其规模（座位 6×7、课表 8~12 节）远未到需要窗口化的程度。结论与替代方案见 [优化计划.md](../优化计划.md) 的 D1.1。
- **Login.vue**：覆盖了安装后首次进入、常规登录、离线恢复、找回密码等多条路径，是全应用唯一不显示侧边栏的全屏页面。

## 页面 ↔ 后端路由对应情况

业务页面基本做到「**一个页面对应后端一个 js**」。以下为不完全 1:1 的情况（均为刻意设计，不是冗余重复）：

| 页面 | 对应后端 | 为何不是严格 1:1 |
| --- | --- | --- |
| `ClassroomView`（学生表）/ `FeeManagement`（班费表） | `routes/dynamicTable.js` + `services/tableService.js` | 两张表都是「动态列」表格，共用同一套 CRUD 工厂（按表名参数化生成路由）。二者曾各有一份独立实现（`students.js` / `feeRecords.js`），因与 `tableService` 逐行重复、且**从未被挂载**，已作为死代码删除 |
| `ClassroomView`（班干部 tab） | `routes/cadres.js` | 与学生表同页不同 tab，后端各自独立 |
| `ActivitiesView` | `routes/activities.js` + `routes/countdowns.js` | 同一页承载「日常活动 / 倒计时」两个独立数据模型 |
| `DashboardView` | `routes/widget-settings.js` + 多个业务接口（经 `composables/useDashboardData.js`） | 首页看板天然跨模块只读聚合 |
| `SettingsView` | `routes/account.js` + `routes/widget-settings.js` + `routes/undo.js` | 设置页聚合账号、小组件、撤销三类；原独立页 `WidgetSettingsView`（`/widget-settings`，无任何入口）已并入此页并删除 |
| `Login.vue` | `routes/auth.js` + `routes/account.js`（`restore-offline`） | 登录页含离线恢复分支 |
| 所有编辑类页面 | `routes/undo.js` | 撤销/重做是横切能力，不属于单一页面 |

其余页面均为一对一：`DutyView`→`routes/duty.js`、`ScheduleView`→`routes/schedule.js`、`SeatView`→`routes/seats.js`、`ScoreManagement`→`routes/scores.js`、`LeaveManagement`→`routes/leaves.js`、`GroupManageView`→`routes/groupManage.js`、`AlbumView`→`routes/album.js`、`AiAssistant`→`routes/ai.js`。

> 说明：`duty.js` 与 `schedule.js` 的周历史快照四组路由逻辑同构，已抽到 `routes/historyRoutes.js` 共用；`seats.js` 的 `seat_history` 表结构不同，未并入该工厂。
