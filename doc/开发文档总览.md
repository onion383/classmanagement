## 一、整体架构

应用分为三层，运行在三个进程/上下文里：

```
┌─ Electron 主进程（Node 环境）──────────────────────────────┐
│  electron/main.js                                         │
│  ├─ 窗口管理：主窗口 / 引导窗口 / 迁移窗口 / 小组件窗口         │
│  ├─ electron/main.*.js 拆分模块                            │
│  │   backend  perf  tray  widget  protocol  updater       │
│  │   dialogs  apps  usb  config  window-material          │
│  │   startup-timer  privateWorkingSet                     │
│  └─ 启动计时、打包精简（afterPack / inno）                   │
└───────┬───────────────────────────┬───────────────────────┘
        │ IPC（preload 白名单）       │ child_process.fork
        ▼                           ▼
┌─ 渲染进程（Vue 3 前端）───────┐  ┌─ 后端进程（Express 5）────────┐
│  student-frontend/           │  │  student-backend/app.js      │
│  index.html / setup.html     │  │  routes/*  服务各业务接口      │
│  migration / widget /        │  │  services/* 加密通道/媒体/表服务│
│  desktop-widget 等入口        │  │  db.js 数据访问（多加密库）    │
│  src/{views,components,      │  │  监听 127.0.0.1:3000         │
│       composables,stores,    │  └──────────┬───────────────────┘
│       styles,router,utils}   │             │
└──────────┬───────────────────┘             ▼
           │  HTTP（axios + 安全通道加密）  ┌─ 本地加密 SQLite ─┐
           └──────────────────────────────►│ index.db（登记）  │
                                           │ <班主任>.db（业务）│
                                           └───────────────────┘
```

### 关键机制

- **进程模型**：主进程负责窗口、系统集成与后端子进程的生命周期；后端被 `child_process.fork` 拉起（开发用系统 node，打包后用 `electron.exe` + `ELECTRON_RUN_AS_NODE`），仅监听 `127.0.0.1`。
- **IPC 白名单**：渲染进程不能任意调用主进程能力，所有通道在 [preload.js](../electron/preload.js) 中显式登记（invoke / send / on 三类白名单）。
- **前端加载**：打包后用自定义 `app://` 安全协议加载（而非 `file://`），以获得可持久化的 origin（localStorage 才不会每次启动被清空）。
- **通信与安全**：前端通过 axios 访问 `http://localhost:3000`；请求/响应体经安全通道加密（ECDH P-256 协商 + HKDF 派生 + AES-256-GCM），后端 `services/secureChannel.js` 与前端 `composables/secureAxios.js` 一一对应。
- **启动与可靠性**：主进程有心跳与看门狗；后端异常会触发重连/重启广播；启动耗时由 `startup-timer` 采集（口径为「后端就绪 + 首屏渲染完成」）。
- **数据**：本地加密 SQLite。`index.db` 是加密的登记表，每位班主任对应一个自含的加密库；`db.js` 通过 `AsyncLocalStorage` 把 `db.prepare` 转发到当前请求绑定的库。
