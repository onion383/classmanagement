# 班集 · 代码审查报告（前端）

> 本目录记录对前端 JavaScript / Vue 代码的**只读审查**结果。不含任何代码改动。
> 审查时间：2026-10-25 ｜ 范围：`student-frontend/src/`（167 个 .js/.vue 文件）
> 约定：每条给出「文件:行号 + 问题代码 + 量化影响 + 具体改法」，按严重度排序。

## 一、总体评价

**前端工程质量高，且已形成稳定的性能自觉。** 值得记录的做法：

- **渲染性能有实测支撑的优化**：`useTableCRUD.js` 的 `displayList` 明确注释了「复用行对象引用，不再逐行 `{...}` 拷贝……实测 ~29ms」，并用 `performance.mark/measure` 做归因探针。
- **流式响应有正确的中断机制**：AI 聊天用 `AbortController`（`composables/ai/aiChat.js:235`），能真正掐断上游模型请求。
- **请求去重有模块级缓存**：`useDashboardData.js` 用 `dataCache` + `pending` 双缓冲，避免 Dashboard 挂载时重复发同样请求。
- **竞态有丢弃保护**：`SearchDialog.vue` 远程搜索在响应回来时比对关键字，丢弃过期响应。
- **blob 有生命周期管理**：`useThumbBatch.js` 维护 `liveUrls` 集合 + `prune()`，切相册/销毁时 `revokeObjectURL`，并用 `inflight` 合并重复请求。
- **弱引用缓存用得对**：`DynamicTable.vue:643` 的收据数量缓存用 `WeakMap` 键为行对象，不参与响应式、也不阻止 GC。
- **既有优化已充分**：虚拟滚动全面虚拟化、GridView 只做限高、表头先行行后填、Dashboard 骨架屏是唯一例外。

发现的问题**均为"可优化但非紧急"**，无结构性缺陷。

## 二、发现清单

### [低-中] 排序比较器中直接调用 `localeCompare`，未复用 Intl.Collator

- **状态**：**已实施**（2026-10-26）。新增 `src/utils/collator.js` 统一管理两个比较器，6 个调用点改为复用；等价性与性能验证见下。
- **文件**（6 处调用，7 行）：

  | 文件:行 | 场景 |
  | --- | --- |
  | `composables/useTableCRUD.js:86` | **表格主排序**（点击表头排序，每次都重跑） |
  | `components/tables/DynamicTable/DynamicTable.vue:942` | **列筛选下拉排序**（每次展开筛选面板） |
  | `components/import-export/ExportAlbumIndex.builder.js:57` | 相册索引导出，文件名自然排序 |
  | `views/LeaveManagement.vue:456` | 请假统计按姓名排序 |
  | `views/ScoreManagement.vue:307` | 加减分按时间排序 |
  | `components/base/LeaveTimeline.vue:121` | 请假时间线排序 |
  | `components/import-export/ExportAlbumIndex.builder.js:57` | 同上（带 `numeric` 选项） |

- **代码**（`useTableCRUD.js:86`，主排序路径）：

```js
return String(va).localeCompare(String(vb), 'zh') * (sortOrder.value === 'asc' ? 1 : -1)
```

- **问题**：`String.prototype.localeCompare` 每次调用都要**新建一个 Collator**（规范允许引擎缓存，但多数实现仍要走一遍 collator 构造 + 区域数据查询）。而排序比较器会被调用 **O(n log n)** 次。
- **实测影响**（本机实测，Node v22.22.2，1000 条中文姓名）：

  | 写法 | 排序耗时 |
  | --- | --- |
  | 每次调用 `localeCompare` | **9.9ms** |
  | 预建一个 `Intl.Collator('zh')` 复用 | **1.4ms** |

  **快 7 倍，且排序结果逐位一致**（已验证 `JSON.stringify` 相等）。

- **实际影响评估**：班级规模通常 40–60 人，排序耗时在 0.5ms 量级，**用户基本无感**。因此定级为「低-中」而非「中」——收益存在但不紧迫。真正会放大的场景是：① 装了 `xlsx` 的全量名单（可达数百行）；② 未来引入多班数据合并。
- **实际改法**：新增 `src/utils/collator.js` 统一管理两个比较器（`zhCollator` / `naturalCollator`），6 个调用点改为复用。**参数与原先的 `localeCompare` 调用逐一对应**，避免排序结果变化。

  ```js
  // src/utils/collator.js
  export const zhCollator = new Intl.Collator('zh')
  export const naturalCollator = new Intl.Collator('zh-Hans-CN', { numeric: true, sensitivity: 'base' })
  ```

  **注意**：`ExportAlbumIndex.builder.js:57` 用的是带 `{ numeric: true, sensitivity: 'base' }` 的**定制选项**，必须用 `naturalCollator`（不能与通用的 `zhCollator` 混用），否则文件名排序会从「1、2、10」变成字典序。
- **验证**（[testjs/collator-equiv-probe.js](../../testjs/collator-equiv-probe.js)，**4/4 通过**）：
  - 200 个中文名排序结果**逐位一致**；边界值（空串/数字/中英混排）与数字字符串排序结果均一致。
  - 文件名自然排序结果一致（`1.jpg 2.jpg 3.jpg 10.jpg 20.jpg a.jpg B.jpg IMG_001.png …`）。
  - 性能：1000 条 × 20 轮，**36.9ms → 14.4ms（快 2.6 倍）**。
  - `vite build` 通过（产物已清理）。
- **风险**：极低。行为等价，已验证。

## 三、已排查且确认无问题的项

以下是本轮重点检查、**结论为健康**的方向，记录在案以免重复排查：

| 检查项 | 结论与依据 |
| --- | --- |
| **Excel 导入主线程解析** | `ImportExcel.vue:137` 的 `XLSX.read` 在主线程，但实测 500 行 22.5ms、2000 行 45.9ms、5000 行 72.2ms，**线性增长且绝对值可接受**；导入是一次性操作，不构成问题 |
| **事件监听泄漏** | `App.vue` 的 `app-visible` 两处监听均在回调内自 `removeEventListener`（327、362 行），`beforeUnmount` 解绑其余三个；`useTableCRUD` 的防抖定时器在 `onBeforeUnmount` 清理 |
| **请求竞态** | `SearchDialog` 有关键字比对丢弃机制；AI 流式用 `AbortController`；Dashboard 用 `pending` Promise 去重 |
| **响应式陷阱** | `watch` 多用 getter 形式（`watch(() => props.visible, ...)`），`deep: true` 仅 5 处；模板内无内联对象/数组创建 |
| **强制重排** | 157 处布局读取**全部集中在拖拽/几何测量场景**（`GridView.drag.js` 27 处、`DynamicTable.drag.js` 26 处），属必要开销 |
| **blob 泄漏** | `useThumbBatch.js` 有 `liveUrls` 集合 + `prune()` + `revokeAll()`；`inflight` 集合合并重复请求 |
| **大列表渲染** | 已全面虚拟化（`virtualFrom` default=1）；GridView 限高 + 吸顶表头 |
| **弱引用使用** | `DynamicTable.vue:643` 收据计数用 `WeakMap` 键为行对象，不参与响应式 |
| **深拷贝** | `JSON.parse(JSON.stringify(...))` 仅 3 处，且对象都很小（设置分区配置、排班默认项） |

## 四、优先处理建议

1. **`Intl.Collator` 复用**（唯一有实际收益的项）——改 7 处，其中 2 处是高频路径（表头排序、筛选下拉）。改动小、收益明确、风险极低。
2. 其余**建议不动**。前端已无结构性问题。
