## 一、总体结论

**这套代码的工程质量高于一般水平，没有发现结构性缺陷。**

值得记录的事实：SQL 拼接全部有白名单前置校验、缓存有 LRU/字节封顶淘汰、事务边界正确、同步 IO 在运行期已用内存索引规避、注释普遍记录「为什么」而非「是什么」、多处性能优化带实测数据支撑。

真正的问题只有 3 个，且**都不紧急**。

## 二、问题分级总览

| # | 严重度 | 问题 | 位置 | 实测影响 | 建议 |
| --- | --- | --- | --- | --- | --- |
| 1 | **中** | bcrypt 同步调用阻塞事件循环 | `routes/account.js`（7 处）、`routes/auth.js`（7 处） | `hashSync(cost=10)` **64.6ms**、`compareSync` **56.2ms**、cost=12 达 226ms | 改用 `bcryptjs` 的 Promise 版 API |
| 2 | **低-中** | 排序比较器未复用 `Intl.Collator` | 前端 7 处（`useTableCRUD.js:86`、`DynamicTable.vue:942` 为高频路径） | 1000 行排序 **9.9ms → 1.4ms**（快 7 倍，结果一致） | 模块级预建 Collator 复用 |
| 3 | 低 | 班干部职务树 N+1 查询 | `routes/cadres.js:24`、`:81` | 10–20 次查询，个位数毫秒 | **建议不动**（收益 < 风险） |

## 三、值得优先处理的一件事

**只有第 1 项（bcrypt 异步化）值得动手。**

理由：它是唯一一个「会真实影响用户体验」的问题——登录、改密码、注册这些用户高频且在意的操作，每次都会让整个后端的事件循环停顿 60ms 以上。期间桌面小组件的心跳、正在进行的相册缩略图批量请求都会被卡住。用 `bcryptjs` 自带的 Promise API 机械替换即可，改动约 14 处，风险低。

第 2 项（Collator 复用）收益明确、风险极低，可以顺手做——但班级规模下用户基本无感，不急。

第 3 项及审查中排除了大量疑点的其他候选（职务树 N+1、Excel 主线程解析、主题 store 监听未解绑、App.vue 事件泄漏等），**都建议不动**：改了没收益，不改没风险，改动反而引入回归风险。

## 四、本次审查的「已排除」清单

以下是审查过程中重点检查、**经核实确认健康**的方向。记录在案，避免日后重复排查，也说明为什么最终只有 3 个问题。

### 后端

| 检查项 | 结论 |
| --- | --- |
| SQL 注入 | 88 处 `prepare()` 字符串拼接全是表名/列名（标识符无法参数化），**每个拼接点前都有白名单校验**；值一律 `?` 绑定 |
| 缓存无上限增长 | `connCache` LRU 上限 10（超限关闭连接）；`bufCache` 字节封顶 64MB + 失效钩子 |
| 事务原子性 | 多表写/级联删/跨表操作均包在 `db.transaction()` 内；`account.js` 显式处理了「先换包裹再改密码」的顺序依赖 |
| 同步 IO | 56 处集中在启动期与一次性路径；运行期热路径已规避（`albumThumbs` 注释记录了实测数据） |
| 正则回溯 | 未发现危险模式（均为简单量词，无嵌套量词） |
| 定时器泄漏 | 后端几乎无 `setInterval`；`sessions` / `usedNonces` 有 TTL 清理 |
| 未捕获异常 | 33 处 `catch` 多为「可忽略」语义；无 unhandled rejection 风险点 |
