# 班集 · 优化文档

本文记录「班集」项目中**已经实施的优化**，按五个维度归类：打包文件体积、磁盘占用体积、内存占用、首批加载、切换性能。每条说明「做了什么 / 为什么 / 效果或依据 / 涉及文件」。

逐文件说明见 [主进程/主进程.md](./主进程/主进程.md)、[后端/后端.md](./后端/后端.md)、[前端/前端总览.md](./前端/前端总览.md)。

## 一、打包文件体积

目标：减小安装包与解包产物体积，同时不牺牲功能与合规。

### 1.1 运行时组件裁剪（`afterPack` 钩子）

由 `electron-builder.json` 的 `afterPack` 调用 [afterPack.js](../electron/afterPack.js)，仅对 win32 产物生效：

| 处理 | 内容 | 效果 / 依据 |
| --- | --- | --- |
| 删除软件 Vulkan 回退 | `vk_swiftshader.dll`、`vk_swiftshader_icd.json`、`vulkan-1.dll` | 约 **-6.1MB**；应用不使用 WebGL/WebGPU，CDP 核对删除前后渲染一致 |
| 删除 DirectX 着色器编译器 | `dxcompiler.dll`、`dxil.dll` | 约 **-25.9MB**；删除后 GPU 进程仍为硬件加速 ANGLE/D3D11，控制台无报错 |
| 压缩 Chromium 许可聚合文件 | `LICENSES.chromium.html` → `third-party-licenses.zip`（自实现 CRC32 + `deflateRawSync`，零依赖） | 约 **19.4MB → 2.1MB（-17.3MB）**；声明仍随包分发，合规成立（红线：不得改为联网下载） |

明确保留（勿删）：`libGLESv2.dll` / `libEGL.dll` / `d3dcompiler_47.dll`（ANGLE 硬件加速必需）、`icudtl.dat`、`resources.pak`、`v8_context_snapshot.bin` / `snapshot_blob.bin`、`ffmpeg.dll`（相册视频播放）。

### 1.2 打包排除规则（`electron-builder.json`）

- `compression: "maximum"`，`win.target: "dir"`。
- `files` 中大量排除：原生依赖源码与头文件（`*.h/*.hpp/*.hh`）、`*.md`、`*.map`、`*.d.ts`；非本平台预编译产物（`better-sqlite3-multiple-ciphers/prebuilds/linux*·darwin-*·win32-arm64`）；`pdfjs-dist`、`@napi-rs`；`pdf-parse` 的 `web/esm/worker/node/bin`；`mammoth` 浏览器版与测试；`jszip`/`xlsx` 多余分发文件；`koffi` 的 `src/vendor`；`trash` 的 macos 脚本。
- `asarUnpack` 仅解包必要项：`resources/ffmpeg/**`、`**/student-backend/**`、`node_modules/**`、`**/*.node`。
- `electronLanguages: ["zh-CN", "en-US"]`：只保留中英两套 Chromium 语言包。
- `npmRebuild: false`：`koffi` 等使用预编译 N-API 绑定，免 `node-gyp`/`electron-rebuild`，无需重建。

### 1.3 前端构建精简

见 [vite.config.js](../student-frontend/vite.config.js)：

- `build.target: 'chrome120'`：运行环境只有 Electron 内嵌的新版 Chromium，显式现代目标，避免向下转译产生多余体积与解析开销。
- `modulePreload: { polyfill: false }`：Chromium 原生支持 `modulepreload`，关掉 Vite 注入的 polyfill（否则被打进入口 chunk）。
- `emptyOutDir: true`：清空输出目录，避免旧 hash 文件残留被打进安装包。
- 大体积第三方库（exceljs 908KB、xlsx 415KB、jspdf 390KB、html2canvas 195KB 等）被拆成独立 chunk，按需加载（见「切换性能」）。

### 1.4 后端重依赖处理

- **重依赖懒加载**：`app.js` 顶层只加载登录必需路由，`sharp`、`pdf-parse`、`mammoth`、`xlsx`、`multer` 等延后到 `setImmediate` 再 `require`，避免启动时把 `.node` 与大量 JS 一次性载入。
- **替代巨型依赖**：`services/pdfDomShim.js` 用纯 JS 的 `DOMMatrix` 补丁替代 `@napi-rs/canvas`（约 **35MB**）。
- **FFmpeg 随包分发**：`resources/ffmpeg/**` 预置 LGPL 版 FFmpeg（约 6.5MB），不做「按需联网下载」，避免用户下载失败与 LGPL 合规风险（红线：合规优先于体积）。

## 二、磁盘占用体积

目标：控制「安装后随运行不断增长」的缓存与日志，避免磁盘占用随时间膨胀。

### 2.1 渲染进程 V8 代码缓存

[protocol.js](../electron/main/protocol.js) 的 `setupRendererCodeCache()` 把构建产物 JS 的「解析 + 编译」结果缓存到 `userData/renderer-code-cache`，第 2 次及以后启动直接复用。缓存条目按内容哈希命名，应用更新后旧条目永不命中、会持续累积（注释记录实测可达 **50MB+**），故 `pruneStaleCodeCache()` **按应用版本号做一次性清理**：版本未变则零开销返回，版本变化时后台异步删除旧条目（不阻塞启动，删除失败静默，下次再试）。

### 2.2 Node 模块编译缓存

[config.js](../electron/main/config.js) 的 `resolveCompileCacheDir()` 指向 `userData/node-compile-cache`，缓存主进程加载的模块字节码，随版本/源码变更自动失效重建。

### 2.3 缓存目录可迁移

`app-config.json` 支持把「数据目录」「相册缩略图目录」配置到独立位置（`resolveDataDir` / `resolveThumbsDir`），便于用户把大体积缩略图缓存与业务数据分离存放。

### 2.4 运行期目录

- 相册缩略图缓存在 `dbManager.thumbsDir`（文件名 `{photoId}.jpg`）；删除照片时 `albumOps.deleteThumb` 同步清理缩略图。
- 相册回收站 `album-trash`（`albumOps.moveToTrash`），避免误删即永久丢失。
- 日志：`userData/data/backend.log`（后端 stdout/stderr）、`userData/data/startup.log`（启动时间线，追加写入）。

## 三、内存占用

### 3.1 工具箱浮窗「隐藏即销毁」

[widget.js](../electron/main/widget.js) 的会话级显隐采用「隐藏即 `destroy`」策略（而非仅 `hide`），以释放整个渲染进程；恢复时用 `lastWidgetBounds` 复原位置。桌面小组件按启用状态创建/销毁。

### 3.2 数据库连接 LRU 缓存

[dbManager.js](../student-backend/dbManager.js) 的 `connCache` 按 slug 缓存已打开连接，上限 `CONN_CACHE_MAX = 10`，超出按 LRU 关闭驱逐（`touchConn`/`setCachedConn`/`evictConn`），限制多账号场景下的连接堆积。

### 3.3 页面缓存上限

前端 `App.vue` 用 `<KeepAlive :max="16">` 缓存页面，限制常驻内存的页面组件数量。

### 3.4 监听器正确解绑

[preload.js](../electron/preload.js) 的 `listenerMap` 保存「用户 callback → 包装 wrapper」映射，`off` 时据此取出真正的 wrapper 再 `removeListener`，避免因引用不同无法解绑造成内存泄漏。

### 3.5 SQLite 内存 PRAGMA

`dbManager` 打开连接时设置 `busy_timeout=5000`、`journal_mode=WAL`、`synchronous=NORMAL`、`cache_size=-20000`（约 20MB 上限）、`temp_store=MEMORY`。

### 3.6 内存度量口径（可观测）

- [privateWorkingSet.js](../electron/main/privateWorkingSet.js) 用 koffi 调 `pdh.dll` 读 Windows「`\Process V2(*)\Working Set - Private`」，得到与任务管理器「进程」页一致的**专用工作集**口径（Electron 自带的 `workingSetSize`/`privateBytes` 均对不上）。
- [perf.js](../electron/main/perf.js) 汇总逐进程内存（主进程 / 各渲染窗口 / GPU / 服务进程 / 后端），后端由 `process.memoryUsage()` 自报；并做后台定时采样（5s 一次）给出「总计 / 近一分钟均值 / 自启动峰值」。
- **手动 GC**：`perf-gc` 触发主进程 `global.gc` + 各渲染进程 CDP `HeapProfiler.collectGarbage` + 后端自报 GC（后端以 `--expose-gc` 启动）。

## 四、首批加载

目标：缩短「点开应用 → 首屏可用」的时间，并保证计时口径可量化。

### 4.1 主进程启动并行化

- **主窗口与后端并行启动**：`main.js` 在建窗之后 fork 后端，不等待后端就绪即建窗（详见 [主进程/主进程.md](./主进程/主进程.md) 4.4）。
- **开发模式秒出画面**：先 `loadURL` 一份内联 `data:text/html` loading 页，后台 `pollViteAndNavigate` 轮询 Vite 就绪后再导航。
- **打包模式静态占位**：`app://local/setup.html` / `index.html` 内联 splash 占位，不依赖 JS，先出画面。
- **显示时机**：`show:false` 创建，`ready-to-show` 再 `show`，另有 1500ms 兜底 `revealWindow`；`revealWindow` 显示前对 win32 再次应用亚克力材质。

### 4.2 `app://` 协议性能

[protocol.js](../electron/main/protocol.js)：

- 启动时只 `readdir` 一次拿到顶级 html 入口名单，之后**纯按路径规则流式返回**，不做任何逐请求同步 `fs`（原 `existsSync + statSync` 会阻塞主进程）。
- 带 hash 的静态资源（js/css/wasm/图片/字体）设 `public, max-age=31536000, immutable` 长缓存，后续启动直接命中 Chromium 磁盘缓存；其余 `no-cache`。
- `app://` 声明 `standard + secure + supportFetchAPI + corsEnabled + stream + codeCache`，成为**真实且持久化的 origin**，解决 `file://` 下 `localStorage` 每次重启清空（反复登录、设置还原）的问题。

### 4.3 后端启动优化

[app.js](../student-backend/app.js)：

- **关键路由立即加载**（`auth`/`account`/`students`），非关键路由与 `sharp`/`pdf-parse` 等重依赖用 `setImmediate` 逐个懒加载，不阻塞就绪信号。
- **就绪即上报**：`app.listen` 回调内 `process.send({ type:'backend-ready' })`，前端据此在就绪瞬间发首个请求，不再靠固定退避重试「撞」端口。
- **后台暖机**：就绪后 `setImmediate(() => dbManager.warmup())`，把「加载 sqlite 原生模块 + 打开库并建表」的一次性冷启动成本放到首个用户请求之前。

### 4.4 前端首屏

- **Vite 预热模块图**：[vite.config.js](../student-frontend/vite.config.js) 的 `server.warmup.clientFiles` 预编译入口、首屏落地页（Login / Dashboard）、引导页与关键依赖，避免首个请求才逐文件编译导致白屏。
- **CSS 非阻塞**：自研 `nonBlockingCss` 插件把构建产物 `<link rel="stylesheet">` 改为 `media="print" onload="this.media='all'"`，首帧不被全量 CSS（约 120KB）阻塞；渲染层移除 splash 前会再等样式表就绪，不出现无样式中间态。
- **splash 保活策略**：首屏占位保活至「backend-ready + 路由就绪 + 样式就绪」三者满足；启动失败时提供「重启后端 / 退出」兜底。
- **落地页预加载**：Vue 初始化前先写入主题 CSS 变量（避免首屏闪烁），并预加载落地页组件。

### 4.5 启动耗时计量（可量化）

[startup-timer.js](../electron/main/startup-timer.js)：

- 以模块加载时刻为起点，`mark(name)` 记录时间戳；`end(name)` 定死「启动完成」锚点（幂等），`getTimeline().total` 优先取锚点，不再被更晚的 mark 抬高。
- **锚点口径**（`main.js` `tryEndStartup`）：「上次启动耗时」= **「后端就绪」与「首屏渲染完成」两者都满足**的那一刻（取较晚者），最接近「点开就能用」。
- 渲染层 `[startup]` 日志经主进程 `webContents.on('console-message')` 采集为 mark；仅采集**首次加载**（`rendererStartupLogged` 停收机制），避免前端重启把这些日志以主进程已运行时长为基准重复计入。
- 输出：`whenReady` 后 5s 打印时间线并追加写入 `startup.log`；性能面板经 `perf-startup` 读取。

## 五、切换性能

目标：让页面/路由切换、弹窗打开尽量「点开即有」。

### 5.1 路由懒加载 + 空闲预取

- 路由组件懒加载（`router/index.js`），进入首页时 `ensureDashboardData()` 并发拉取看板数据。
- `prefetchRoutes()` 在空闲时**逐条 + 让出空闲**地预热所有懒加载路由 chunk，避免点击侧边栏时才下载/解析。
- `routePrefetch` 悬停预取路由 chunk。

### 5.2 弹窗与组件预取

- 弹窗组件异步加载 + `v-preload` 指令（悬停 80ms 防抖预取），减少「点开弹窗」的等待。
- `<KeepAlive :max="16">` 缓存已访问页面，回退时无需重建。

### 5.3 静态资源与媒体

- `app://` 协议的 hash 资源设为 `immutable` 长缓存，二次访问直接走 Chromium 磁盘缓存（见 4.2）。
- 相册缩略图缓存到 `thumbsDir`（`{photoId}.jpg`），已生成则直接复用；`sharp` 生成缩略图时有**全局并发信号量（最多 2 个任务）**，避免并发过多拖慢切换。
- 视频封面用 FFmpeg 抓帧一次后缓存。

### 5.4 大库按需分包

exceljs / xlsx / jspdf / html2canvas 等仅在「导入导出 / 打印」时才用到的库被拆成独立 chunk，只在对应操作时加载，不进入首屏与页面切换的关键路径。
