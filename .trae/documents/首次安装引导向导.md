# 首次安装引导向导（First-Run Setup Wizard）

## Context

当前应用**没有任何首次运行检测**：任何一次启动都直接创建主窗口并落到登录页，新用户必须自己在登录页手动「注册」才能开始使用。这对全新安装的用户不友好，也缺少一个统一设置「保存方式 / 账号 / 班级信息 / 主题 / 存储目录」的入口。

本方案新增一个**首次安装引导向导**：全新安装（本机无任何有效账号）时，先弹出独立的引导窗口，用户按步骤完成初始化后，才创建主窗口进入正式使用。后续启动不再出现。

用户已确认的交互要求：
- 是**向导**，但采用**左右两栏**：左栏只做**进度展示**（不可点击切换），右栏是当前步骤内容。
- 侧栏**共 5 行**、分两组：「项目」（账户设置 / 班级设置 / 主题选择）与「具体设置」（储存设置 / 性能优化）。
- 「账户设置」是一个**复合大步骤**，内含 3 个子步骤：**保存方式**（密文/明文）→ **账户信息**（用户名/密码/确认密码）→〔条件〕**恢复密钥**（仅「密文 + 已填密码」时出现，否则跳过）。
- **必填**：用户名、密码（仅密文）、确认密码、班级名称；其余可留空用默认。
- **默认值**：保存方式默认「**密文保存**」；主题默认「**毛玻璃（glass）**」；储存目录默认 `userData/data`。用户若一直点「下一步」不改动任何可选项，即按这些默认值落地。
- **明文模式下不允许设置密码**（保存方式确认必须在账户设置之前）。
- 密文 + 设了密码 → 增加「抄写 12 词恢复密钥（确认前 3 词）」子步骤；**未填密码或明文模式则跳过该步骤**。
- 主题选择放在班级设置之后，带一小块预览 UI，选择后**立即应用**到引导窗口。
- 性能优化：**窗口一打开就后台开始**；到达该步时若已完成 → 提示「优化已自动完成~」，未完成 → 显示进度条（可继续等待，不阻塞下一步）。
- 底部按钮：**上一步 / 下一步**（**不要「跳过引导」按钮**）。
- 固定窗口大小 + 毛玻璃主题（跟随已选主题）。

## 设计

### 1. 首次运行检测（Electron 主进程）

新增 `waitBackendReady(timeout)`：轮询后端 `GET /api/auth/accounts`，直到返回 200；用于等待后端就绪后再判断首启。

`app.whenReady()` 分支调整：
- 若回顾到 `registryListValid()` 为空（`/api/auth/accounts` 返回空数组）→ 判定为**首次安装** → `createSetupWindow()`；
- 否则 → `createMainWindow()`（原逻辑）。
- 提供开发期强制开关（环境变量 `FORCE_SETUP=1`）便于反复调试引导流程。

> 说明：向导**必填用户名/密码/班级名**，完成后本机必然存在有效账号，因此无需额外写「已引导」标记；中途退出（未完成账号创建）则下次仍会进入向导，符合预期。

### 2. 引导窗口（Electron 主进程）

新增 `createSetupWindow()`，以 `createMigrationWindow` 为模板：
- 固定尺寸（建议 `860 × 600`，`resizable:false` / `maximizable:false`）、`frame:false`、`transparent:false`、`backgroundMaterial:'acrylic'`、`backgroundColor:'#f0f4f8'`、`center:true`。
- 复用同一 `preload.js`；关闭受 `setupRunning` 守卫拦截（无跳过/取消）。
- 加载新的 `setup.html`（dev 走 `https://127.0.0.1:5173/setup.html`，prod 走 `app://local/setup.html`）。

### 3. 预热编排（性能优化步骤的真实内容）

引导窗口一打开即由主进程启动预热，**后台并行**执行并推送进度：
1. 后端就绪（`waitBackendReady`）——真实等待；
2. 数据目录 `index.db` / schema 初始化（后端首次打开库时完成）；
3. **编译缓存预热**：为后端 fork 注入 `NODE_COMPILE_CACHE`（指向 `userData/node-compile-cache`），并在主进程入口最顶部调用 `module.enableCompileCache(...)`（必须在任何 require 之前）。
4. 主进程记录「预热是否完成」；到达该步时若已完成 → 前端显示「优化已自动完成~」；未完成 → 显示进度条。
- 注：编译缓存的收益在**后续启动**（实测约 200 ms 量级），因此该步**不阻塞**用户下一步。

### 4. IPC 通道（main + preload 白名单）

新增 send/invoke 通道（同步更新 [preload.js](file:///d:/code/Webapp/project-name/electron/preload.js#L26-L65) 白名单）：
- `setup-ready`（send）：渲染层挂载完成回报（对齐 `migration-ready`）。
- `setup-complete`（send）：向导完成 → 主进程关引导窗口、`createMainWindow()`、附带提示条「初始化完成，欢迎使用」。
- `set-initial-data-dir`（invoke）：**首次建库前**写入 `app-config.json` 的 `dataDir`/`thumbsDir`，**不做任何搬迁**（与运行期的 `set-data-dir` 迁移流程严格区分）。
- `get-setup-warmup`（invoke）：取当前预热进度/完成态（供晚挂载的渲染层补齐状态）。
- 预热进度通过既有 `from-main` 推送（`{ type:'setup-warmup', phase, detail, percent, done }`）。

### 5. 后端改动

1. [dbManager.js](file:///d:/code/Webapp/project-name/student-backend/dbManager.js#L280-L293) `createTeacher(username, passwordHash, role, encrypted = true)`：
   - `encrypted=true`：保持现状（生成随机库密钥、`wrapKey`、`registryUpsert(..., 1)`）。
   - `encrypted=false`：以**明文方式**建库（不带 `PRAGMA key`，复用已支持的 `openFile(path, passphrase, encrypted)`），`registryUpsert(slug, username, '', 0)`。
   - 约束：`encrypted=false` 时 `passwordHash` 必须为空（明文库不允许密码）。
2. [routes/auth.js](file:///d:/code/Webapp/project-name/student-backend/routes/auth.js#L105-L166) `POST /register`：
   - 接受 `encrypted`（缺省 `true`，兼容现有调用）。
   - `encrypted===false`：要求无密码 → `createTeacher(uname, '', 'teacher', false)`，并**签发 JWT 返回 token**（供向导继续设置班级信息、进主页）。
   - `encrypted===true && 无密码`：现有无密码分支**补发 token**（当前只返回 user，向导后续需 `PUT /class-info` 需鉴权）。
   - `encrypted===true && 有密码`：保持现有「草稿 + 抄写前 3 词 → `/register/confirm`」流程不变。
3. 班级信息 `PUT /api/widget-settings/class-info` 由向导携带 token 调用（确认其挂在 `auth()` 之下）。

### 6. 前端（新增独立入口 + 页面）

- 新增入口：`student-frontend/setup.html`、`src/setup/main.js`、`src/setup/Setup.vue`；在 [vite.config.js](file:///d:/code/Webapp/project-name/student-frontend/vite.config.js#L55-L62) 的 `rollupOptions.input` 增加 `setup`。
- `src/setup/main.js`：`createApp` + `pinia` + `import '../styles/index.css'` + `useThemeStore(pinia).applyTheme()`（照搬 [migration/main.js](file:///d:/code/Webapp/project-name/student-frontend/src/migration/main.js)）。
- `src/setup/Setup.vue`：
  - **左侧栏（只读进度，5 行）**：两组分区——「项目」（账户设置 / 班级设置 / 主题选择）与「具体设置」（储存设置 / 性能优化），每行显示状态点（已完成/进行中/待完成）；**不可点击**。处在「账户设置」的子步骤时，该行标记为进行中，并在右栏顶部显示子步骤点（1/3、2/3…）指示当前子步骤。
  - **右侧内容区**（`v-if` 按当前步切换）：
    - 「账户设置」大步骤内的 3 个子页面（侧栏同一行，右栏内容切换）：
      1. **保存方式**：单选「密文保存（推荐）/ 明文保存」，**默认选中「密文保存」**；选择驱动后续子步骤的可用性。
      2. **账户信息**：用户名、密码、确认密码；**明文模式禁用密码输入并提示不允许设置密码**。
      3. **恢复密钥**（条件子步：密文 + 已填密码）：调 `POST /api/auth/register` 取草稿与 12 词，展示后要求抄写前 3 词 → `POST /api/auth/register/confirm` 取 token。无密码或明文模式则跳过此子步。
    - 班级设置：班级名称（必填）、班风、学风。
    - 主题选择：`AppSelect`（复用 `themeOptions` 逻辑）+ 一小块预览卡片；**默认「毛玻璃（glass）」**；`@change` 调 `themeStore.setTheme(id)` 即时预览。
    - 储存设置：复用 [SettingsView.vue L257-L290](file:///d:/code/Webapp/project-name/student-frontend/src/views/SettingsView.vue#L257-L290) 的布局与类名；「修改」走 `select-folder` + `set-initial-data-dir`；留空即默认。
    - 性能优化：订阅 `from-main` 的 `setup-warmup`，已完成→「优化已自动完成~」，否则进度条。
  - **底部**：上一步 / 下一步（末步为「完成」）；**上一步/下一步先在「账户设置」的 3 个子步骤间移动**，走完（或跳过）最后子步后才进入「班级设置」；下一步前**校验当前步必填**（缺项定位并提示）。
  - 完成时：写入 `localStorage` 的 `token` / `currentUser`（两窗口同源 `app://local`，主窗口据此直达首页），`PUT /class-info`，再 `send('setup-complete')`。

### 7. 主题一致性

引导窗口与主窗口同源（`app://local`），共用 `localStorage`。默认主题为 `glass`（见 `theme.js` 默认值）；用户在引导内选主题后写入 `localStorage`，主窗口创建时自动继承。

## 验证方式

1. **首启检测**：清空本机账号（或设 `FORCE_SETUP=1`）→ 启动应用 → 出现引导窗口（而非登录页）。
2. **密文 + 密码**：走完保存方式/账户/恢复密钥子步骤，确认恢复词校验通过后才建库；完成后自动进入首页。
3. **明文模式**：选「明文保存」→ 密码输入被禁用 → 完成创建；核对 registry `encrypted=0`、库文件无密码可打开、**无恢复密钥步骤**。
4. **密文 + 无密码**：跳过恢复密钥步骤，创建后能直接进首页（token 已签发）。
5. **主题**：在主题步切换 → 引导窗口即时换肤；进入主窗口后主题一致。
6. **储存设置**：指定自定义目录 → 检查 `userData/app-config.json` 的 `dataDir`/`thumbsDir`；确认数据库**直接建在该目录**（无搬迁动作）。
7. **性能优化**：观察进度；若在到达该步前完成则显示「优化已自动完成~」；重启应用后**不再出现引导**。
8. **构建校验**：清 `node_modules/.cache` 后 `npm run build`，确认产出 `dist/setup.html` 与 `dist/assets/setup-*.js`。
